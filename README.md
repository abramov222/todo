# To-Do List (Vue 3 + Pinia + Vue Router)

Приложение для ведения списка задач с регистрацией, входом и личными списками для каждого пользователя. Задачи можно добавлять через модальное окно, редактировать, удалять, отмечать выполненными и искать по названию; есть светлая и тёмная тема. Состояние хранится в сторах Pinia и сохраняется в `localStorage`, переходами между страницами управляет Vue Router. Оформление на Sass сохранено из лабораторной №4, интерфейс адаптивный и доступный с клавиатуры.

**Автор:** Илья Абрамов, группа ФИТ-241

**Опубликованное приложение:** https://abramov222.github.io/todo/

> **Авторизация учебная.** Сервера нет: аккаунты, хеши паролей и задачи хранятся только в `localStorage` браузера, их может прочитать и изменить любой, у кого есть доступ к этому браузеру. Это не защита настоящих учётных записей. Для проверки используйте только вымышленные email и пароли, которые больше нигде не применяются.

## Технологии

- Vue 3, Composition API (`<script setup>`)
- Pinia — сторы `useTodoStore` и `useUserStore`
- `pinia-plugin-persistedstate` — сохранение сторов в `localStorage`
- Vue Router — страницы, навигация и guard для страницы задач
- Vite — сервер разработки и сборка
- Sass (SCSS): модули `@use`/`@forward`, переменные, карты, миксины, БЭМ; темы через CSS custom properties
- GitHub Actions + GitHub Pages — публикация

## Сторы Pinia

**`useUserStore`** (`stores/user.js`) хранит список зарегистрированных пользователей и `currentUserId` — идентификатор того, кто сейчас вошёл.

- `register()` проверяет формат email, длину пароля, совпадение пароля и подтверждения, отсутствие пользователя с таким email и возвращает ошибки по полям;
- `login()` сверяет email и пароль, `logout()` только сбрасывает `currentUserId` — аккаунты и задачи остаются;
- у каждого пользователя есть постоянный `id` (UUID), email приводится к нижнему регистру, пароль сохраняется как хеш SHA-256.

**`useTodoStore`** (`stores/todo.js`) хранит задачи всех пользователей, у каждой задачи есть поле `userId`.

- геттер `userTasks` отдаёт только задачи текущего пользователя, `doneCount` — число выполненных из них;
- действия `addTask`, `renameTask`, `toggleTask`, `removeTask` работают только с задачами текущего пользователя, новая задача получает его `userId`.

Оба стора подключены к `pinia-plugin-persistedstate` (`persist`), поэтому после перезагрузки страницы восстанавливаются аккаунты, текущий вход и задачи. Страницы не дублируют это состояние: `TodoPage.vue` держит только строку поиска и состояние модального окна, а данные получает и меняет через стор. Задачи из лабораторной №6 (ключ `todo-tasks` без владельца) не переносятся.

## Маршруты

| Адрес | Страница | Доступ |
|-------|----------|--------|
| `#/todo` | `TodoPage.vue` | только после входа |
| `#/login` | `LoginPage.vue` | только гостю |
| `#/register` | `RegisterPage.vue` | только гостю |
| `#/about` | `AboutPage.vue` | всем |

Глобальный guard `router.beforeEach` проверяет `meta.requiresAuth`: гостя, открывшего `#/todo` (в том числе по прямой ссылке или после обновления страницы), перенаправляет на вход, а после входа возвращает на запрошенную страницу. Вошедшего пользователя со страниц входа и регистрации отправляет к задачам. Корень и неизвестные адреса ведут на `#/todo`.

Используется `createWebHashHistory()`: GitHub Pages отдаёт `index.html` только для корня сайта, а часть адреса после `#` обрабатывает роутер, поэтому прямые ссылки на любую страницу открываются без настройки сервера.

## Как проверить

1. Откройте https://abramov222.github.io/todo/#/todo без входа — должна открыться страница входа.
2. На странице «Регистрация» отправьте форму с некорректным email и разными паролями — под полями появятся ошибки.
3. Зарегистрируйте вымышленного пользователя, например `user1@example.test`, с учебным паролем (не меньше 6 символов). После регистрации откроется вход с подставленным email.
4. Введите неверный пароль — появится сообщение об ошибке. Затем войдите с правильным паролем — откроется страница задач.
5. Добавьте несколько задач, отредактируйте, отметьте выполненной, удалите, попробуйте поиск. Обновите страницу — вход и задачи сохранятся.
6. Нажмите «Выйти» и зарегистрируйте второго пользователя (`user2@example.test`) — его список пуст, задач первого не видно. Повторная регистрация с email первого пользователя выдаёт ошибку.
7. Выйдите и снова войдите первым пользователем — его задачи на месте.
8. Откройте страницу «О приложении»: статистика меняется в зависимости от вошедшего пользователя.

## Публикация

Сборка публикуется на GitHub Pages через GitHub Actions (`.github/workflows/ci.yaml`): после push в ветку workflow выполняет `npm ci`, `npm run build` и выкладывает папку `dist/`. В `vite.config.js` указан `base: '/todo/'`, чтобы пути к файлам сборки совпадали с адресом `https://abramov222.github.io/todo/`. В настройках репозитория выбран источник **Settings → Pages → Source: GitHub Actions**.

## Доступность

Сохранены требования A1–A7 из лабораторной №4: все действия выполняются нативными кнопками, ссылками и полями с клавиатуры; у всех полей есть `<label>`; кнопки задач получают имя с названием задачи через `aria-labelledby`; модальное окно возвращает фокус на кнопку, которая его открыла; после удаления фокус переходит на соседнюю задачу; фокус виден у всех элементов, контраст не ниже 4.5:1 в обеих темах.

В новых частях:

- навигация оформлена как `<nav>` со списком ссылок, текущая страница отмечена `aria-current="page"` (его ставит `<RouterLink>`) и подчёркиванием;
- после перехода фокус переносится на заголовок новой страницы, а заголовок вкладки меняется на название страницы;
- ошибки форм связаны с полями через `aria-describedby`, неверные поля отмечены `aria-invalid`, после неудачной отправки фокус переходит на первое поле с ошибкой; ошибка входа объявляется через `role="alert"`.
